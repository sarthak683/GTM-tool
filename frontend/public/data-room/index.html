Expand: L1 / L2 / L3 branching logic
L1 — Solo Director/VP of Implementation, Delivery, or PS
Deep discovery questions, high-level demo only, output glimpses only. Next: mandatory calendar booking for a Demo Deep Dive with a larger audience.
L2 — Larger group (2+ attendees)
Moderate discovery + deep platform demo, output only. Next: mandatory calendar booking to loop in an exec for a technical deep dive.
L3 — SVP+ Executives
Light/embedded discovery, lead with brand vision first, deep demo, output only. Next: mandatory calendar booking for an L1-style discovery + demo, then loop in Operations for deeper analysis.

08 · Internal Setup

POC Setup / Kickoff

NDA signed. Deal logged in CRM (gtm.beacon.li).
🚀 POC Kickoff Template
Prep for Kickoff
AE checks credentials for login access and prepares a set of clarifying questions to get full clarity on the use case. Once success criteria is agreed with the client, the AE sends over an MoM clearly documenting that success criteria and gets client sign-off on it — before the POC officially kicks off.
Step-by-step sequence
  1. AE creates the POC Kickoff document, looping in Harsha (PCS team).
  2. Kickoff document shared with the client.
  3. Once the client approves, PCS validates the POC.
  4. AE coordinates with PCS on timeline, then schedules the Kickoff call.
Dry run demo — internal sync-up
AE runs a dry run of the POC demo internally with the PCS team beforehand. In some cases, the AE also schedules a separate dry run demo with the prospect before the final POC demo takes place in front of the larger group of execs.
Post-agreement — client sync-ups
Once the POC is agreed from the client side and all credentials are received, only if the prospect insists, set up regular sync-up calls with the client to maintain relatability and keep them updated on POC progress.

11 · Internal

Internal Commercial Discussion

Before anything goes to the client, pricing gets aligned internally first.
Step-by-step sequence
  1. Check Metabase for token consumption per session. Sign in with the shared sales@beacon.li account — ask Annie/Shahruk for the password, or take it from the team password manager. (It is deliberately not written here: this page is served as a static file at /data-room/index.html, which needs no login, so anything printed on it is readable by anyone with the URL.)
  2. Run the ROI analysis based on that consumption data.
  3. Discuss commercials with Rakesh before anything is sent to the client.
Metabase — how to pull the token consumption figure
  1. Login to Metabase — new.beacon.li.
  2. Click on the POC Data Requirement tab.
  3. Ask the respective AI engineer working on that project for the session ID, and search for it under the Org ID box.
  4. Once the dashboard auto-populates, check the input tokens consumption range across all the sessions.
  5. For a safe bet — calculate the average of the top 1% of sessions and the top 10% of sessions. That's the token consumption figure you'll use for the ROI Analysis.
